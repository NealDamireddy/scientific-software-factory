# Deployment recovery audit

Only the same-Mac two-replica topology demonstrated continued service at the same API endpoint after one replica stopped. All four loopback trials recovered the same pinned workload outcome (`fbcbe5d9…8b67`). Their recorded workload request sequences also matched. The libSQL run used public reviewer access. The other three exercised named reviewer sign-in.

| Trial and deployment boundary | Observed recovery | Storage tested |
| --- | --- | --- |
| [Single-host SQLite](../variants/single_host/evidence.json), one Mac and one supervised Uvicorn process | The supervisor replaced the child after `SIGKILL`. A full service stop made the endpoint unreachable. The workload verified after restart and again after restore. | SQLite Online Backup copied the live database, including four embedded upload originals. A fresh API runtime opened the copy in a new directory on the same disk. Logical digest, SQLite integrity, foreign keys and API results matched. |
| [Two API replicas](../variants/replicas/evidence.json), one Mac, one proxy and one shared SQLite WAL file | With A’s listener down, the same proxy returned four HTTP 200 order reads from B with identical response hashes. Stopping the remaining processes made the endpoint unreachable. Replacement processes resumed both routes. | The restart reused the same database device and inode. SQLite `quick_check` and the workload passed. Backup and restore remain unverified. |
| [Vercel Blob path](../variants/vercel_blob/evidence.json), pinned Vercel ASGI entry point under local Uvicorn with a loopback Blob sidecar | Stopping the API made the endpoint unreachable. A fresh API process recovered from the original sidecar. A third API process verified the workload against the restored sidecar. The two-process claim race checked claim consistency across API processes. | The backup held the 135,168-byte SQLite snapshot and four separately stored protocol and CSV originals. Restore populated an empty sidecar store on the same Mac with a fresh token. Readback manifests and workload results matched. Live Vercel and private Blob remain unverified. |
| [libSQL](../variants/libsql/evidence.json), local ASGI processes and the official `sqld` 0.24.32 binary on the same Mac, over HTTPS/Hrana | The first endpoint went offline when its API was killed. The replacement used the running SQL process. A peer on a separate port later read the same released order. Killing SQL left `/api/session` at 200 while `/api/orders` returned 503. The workload verified after SQL restarted. | `sqld` reopened its existing data directory. Database failover, backup restore and managed Turso remain unverified. |

**Independent replica check.** I ran the pinned workload against two disposable API processes behind the trial proxy and sharing a SQLite WAL file. After `SIGKILL` of A, six reads went to B and B returned HTTP 201 for a new order. With both replicas killed and the proxy alive, the order endpoint returned 503. A replacement API process read B’s new order and reproduced the original workload outcome.

**Analysis workers.** The single-host and replica trial scripts explicitly relaunched a Mac-local MCP worker with the same identity after a committed claim. Each job recovered with one claim and one submission using a fixed candidate. The Blob and libSQL trials exercised MCP with test clients. The Blob “worker” restart replaced the API process. Off-Mac worker execution, automatic scheduling, takeover by another identity, interruption during a write, and host or disk loss remain unverified across these trials.
