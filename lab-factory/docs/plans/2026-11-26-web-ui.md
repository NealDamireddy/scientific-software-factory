# Lab Factory Web UI Implementation Plan (ambitious scope)

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build Lab Factory's full web product at `lab-factory/web/`. It covers projects and experiments, a coding-tool conversation with plan proposals and build activity, procedures and run plans checked against instrument limits, analysis apps and simulations that really run in the browser, submission history with diffs and traceability, versioned context, per-lab sign-off, the lab's skills, connectors to outside tools, and a page for connecting your own coding agent over MCP or as a skill. It runs on sample data and on a live client written against an HTTP contract that the backend will implement later.

**Architecture:**
- **One statically exported Next.js page** with hash routing.
- **Pure logic in `lib/`:** types, canonical digests, range and tick math, diffing, routing, the sample client and the live client. It has no JSX, uses explicit `.ts` imports and is tested with `node --test`.
- **React screens in `components/`.**
- **Python runs in a hand-written module worker** (`public/runtime/python-worker.mjs`) on Pyodide files that are self-hosted and copied from `node_modules` at build time.

### Exact copy

- **Procedure-level line:** `Only settings shown on a range are checked against your instruments. The rest is written for you and your approver to judge.`
- **Status lines:**
  - `Being revised` (in_progress)
  - `Waiting for sign-off` (in_review)
  - `Signed off by {name} on {date}` (released)
  - `Rejected by {name}: {reason}` (open, with a rejection as the latest event)
  - `Not started` (open, otherwise)
- **Submission summary:** `Submission {n}, all checks passed`, `Submission {n}, 1 check failed`, `Submission {n}, {k} checks failed`.
- **Dates:** `toLocaleDateString("en-GB", { day: "numeric", month: "short", year: "numeric" })`.
- **Sample indicator:** `Sample data. Nothing here is saved or real.`
- **Sign-off buttons:** `Approve submission {n}`, `Reject submission {n}`.
- **Run plan button:** `Send to instrument` (disabled), with the note `Instruments are controlled by the instrument agent, which comes later.`
- **Not found:** `That project or experiment doesn't exist in this lab.` with a link `Go to lab home`.
- **Sign-off rule refusal:** `{name} isn't on this lab's sign-off list.`
- **Stale submission refusal:** `Submission {n} is not the latest. Review submission {latest}.`
- **Readings errors, exactly:**
  - `The file needs a time_s column and an absorbance column.`
  - `Row {r} has a value that isn't a number.`
  - `The analysis needs at least 5 readings.`
- **Runtime errors:** `The analysis runtime couldn't load: {reason}` and `The analysis runtime didn't respond within 60 s. Reload the page and try again.`

### Behavior that must hold

- **The UI never decides pass or fail.** It shows `CheckResult`s, and places markers only from `SettingView.canonical`.
- **Approval always names the latest submission while it's in review.** A name is required, a reason is required to reject, and the lab's sign-off rule applies.
- **Playwright in this sandbox:** `playwright.config.ts` uses `process.env.PLAYWRIGHT_CHROMIUM_EXECUTABLE`, when set, as `launchOptions.executablePath`. Run `PLAYWRIGHT_CHROMIUM_EXECUTABLE=/opt/pw-browsers/chromium npm run test:e2e -- --trace off`. The test timeout is 90 s, because Pyodide needs time to load.

## Review Focus

1. **A malformed readings CSV**, such as missing columns, a text value or too few rows, gets the exact readings error, never a stack trace or a blank result. Tested in Task 3 (unit) and Task 14 (e2e).
2. **The Python runtime fails to load or hangs:** the exact runtime error shows, and the page stays usable. Tested in Task 3 by giving the runner a worker URL that 404s, and a stub worker that never answers with `timeoutMs: 200`.
3. **A stale bookmark with unknown project or experiment ids** shows the not-found copy and a working link home. Tested in Task 8.
4. **A setting outside its limits** puts the marker at the nearest end and shows the failing check's detail. Tested in Task 2 (unit) and Task 12 (seeded run-plan failure).
5. **Double clicks and blank fields in sign-off** produce one outcome, and confirm is disabled while required fields are blank. Tested in Tasks 5 and 15.

The helper modules:
- **`lib/digest.ts`:** `canonicalJson(value: unknown): string` matches Python's `json.dumps(v, sort_keys=True, separators=(",", ":"))`, including `ensure_ascii` escaping of non-ASCII as lowercase `\uXXXX` with surrogate pairs. `sha256Hex(text: string): Promise<string>`. `canonicalDigest(value: unknown): Promise<string>`.
- **`lib/range.ts`:** `markerPosition(value, minimum, maximum): number`. It's clamped to [0, 1], a degenerate range gives 0.5, and NaN gives 0.
- **`lib/ticks.ts`:** `niceTicks(min: number, max: number, count?: number): number[]`, using the 1/2/5×10ⁿ steps. The default count is 5.
- **`lib/diff.ts`:**
  - `type StepChange = { change: "same" | "added" | "removed" | "changed"; before?: number; after?: number; fields?: ("text" | "citations" | "action" | "amounts" | "command" | "settings")[] }`
  - `diffSteps(before: (ProcedureStep | RunStep)[], after: (ProcedureStep | RunStep)[]): StepChange[]`
  - Algorithm: align by the longest common subsequence of each step's key, where the key is `text` for procedure steps and `command` for run steps. A matched pair whose canonical JSON differs is `changed`, with the differing top-level fields listed. Unmatched steps are `added` or `removed`. Output follows the after-order, with removals placed where they occurred.

- **`python/analysis.py`**, exactly this algorithm:

```python
"""Rate of colour loss from absorbance readings (standard library only)."""
import math


def _fit(t, a, k):
    e = [math.exp(-k * x) for x in t]
    n, se, see = len(t), sum(e), sum(x * x for x in e)
    sa, sea = sum(a), sum(x * y for x, y in zip(e, a))
    det = n * see - se * se
    if abs(det) < 1e-12:
        return None
    a_end = (see * sa - se * sea) / det
    amp = (n * sea - se * sa) / det
    sse = sum((y - a_end - amp * x) ** 2 for x, y in zip(e, a))
    return sse, a_end, amp


def analyze(readings):
    t = [float(x) for x in readings["time_s"]]
    a = [float(y) for y in readings["absorbance"]]
    if len(t) != len(a) or len(t) < 5:
        raise ValueError("The analysis needs at least 5 readings.")
    span = max(t) - min(t)
    if span <= 0:
        raise ValueError("time_s must increase.")
    mean = sum(a) / len(a)
    flat_sse = sum((y - mean) ** 2 for y in a)
    lo, hi = math.log(0.01 / span), math.log(50 / span)
    grid = [math.exp(lo + (hi - lo) * i / 400) for i in range(401)]
    fits = [(f, k) for k in grid if (f := _fit(t, a, k)) is not None]
    i = min(range(len(fits)), key=lambda j: fits[j][0][0])
    left = fits[max(i - 1, 0)][1]
    right = fits[min(i + 1, len(fits) - 1)][1]
    for _ in range(60):
        m1, m2 = left + (right - left) / 3, right - (right - left) / 3
        if _fit(t, a, m1)[0] < _fit(t, a, m2)[0]:
            right = m2
        else:
            left = m1
    k = (left + right) / 2
    sse, a_end, amp = _fit(t, a, k)
    rms = math.sqrt(sse / len(t))
    if amp <= 0 or flat_sse == 0 or sse >= 0.9 * flat_sse:
        return {"decay": False, "rms_error": math.sqrt(flat_sse / len(t))}
    return {"decay": True, "rate_constant_per_s": k, "half_life_s": math.log(2) / k,
            "a0": a_end + amp, "a_end": a_end, "rms_error": rms}
```
