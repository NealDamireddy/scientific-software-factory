# Lab Factory Web UI Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build Lab Factory's web UI at `lab-factory/web/`: Lab → Projects → Experiments, a conversation with a collapsible procedure panel and sign-off. It runs entirely on sample data behind a typed client interface.

**Architecture:**
- **One statically exported Next.js page** with hash routing (`#/…`). Every screen reads from a `LabFactoryClient`. In this project the only implementation is an in-memory sample client seeded with the Emory Biophysics lab.
- **Pure logic in `lib/`, React in `components/`.** `lib/` holds the types, range math, routing and the sample client. It has no JSX, imports with explicit `.ts` extensions, and runs under `node --test` directly. `components/` and `app/` hold the React screens.

**Tech Stack:**
- Next.js 16.4.6 (static export), React 19.3.1, TypeScript 5.9.3
- lucide-react 1.72.0
- @fontsource/ibm-plex-sans 5.3.0, @fontsource/ibm-plex-mono 5.3.0
- Playwright 1.65.1, @axe-core/playwright 4.14.1
- Node 22 built-in test runner (`node --test`, native type stripping)

**Spec:** `lab-factory/docs/specs/2026-11-26-lab-factory-web-ui-design.md`

## Global Constraints

- **Isolation.**
  - All code lives in `lab-factory/web/`, apart from one new CI workflow file in Task 9.
  - It imports nothing from the repo root `app/`, from `factory/` or from `lab-factory/src/`.
  - Only unit tests may read `lab-factory/examples/*.json`, and only from disk.
- **Branch:** `lab-factory/web-ui`. Run every command from `lab-factory/web/` unless a step says otherwise.
- **Pinned versions, exactly:** `next 16.4.6`, `react 19.3.1`, `react-dom 19.3.1`, `typescript 5.9.3`, `@types/react 19.3.0`, `@types/node 22.20.5`, `lucide-react 1.72.0`, `@fontsource/ibm-plex-sans 5.3.0`, `@fontsource/ibm-plex-mono 5.3.0`, `playwright 1.65.1`, `@axe-core/playwright 4.14.1`. Commit `package-lock.json`.
- **TypeScript rules for `lib/`:**
  - Code must run under Node type stripping: no `enum`, no `namespace`, no constructor parameter properties.
  - Relative imports end in `.ts`. Set `allowImportingTsExtensions: true` in `tsconfig.json`.
- **Fonts:** IBM Plex Sans for the interface and IBM Plex Mono for code blocks only, both through Fontsource imports. Nothing loads from fonts.googleapis.com.
- **Colors.** These are the only colors except the spectrum:

  | Token | Value |
  |---|---|
  | `--ground` | `#F5F6F4` |
  | `--paper` | `#FFFFFF` |
  | `--ink` | `#1C2133` |
  | `--steel` | `#5F6675` |
  | `--indigo` | `#3B4A8F` |
  | `--sand` | `#F3EBCF` |
  | `--sand-ink` | `#4A3B10` |
  | `--rule` | `#E6E8EC` |

  Failures use `--fail` `#9B2C2C` text on `#FBEAEA`.
- **Spectrum (wavelength strips only):**
  `linear-gradient(90deg, #A898CF 0%, #8C9DD3 17%, #88B6CF 30%, #92BFA3 40%, #B8C98F 50%, #DDD093 60%, #DDB48E 70%, #D29A8A 83%, #B38783 100%)`, spanning 400–700 nm. If an instrument's wavelength range differs, show the slice of the gradient for its own range.
- **Copy rules:**
  - Sentence case.
  - No all-caps labels.
  - No `·` separators in interface text.
  - No `→` appended to buttons or links.
- **Exact copy:**
  - Procedure-level line: `Only settings shown on a range are checked against your instruments. The rest is written for you and your approver to judge.`
  - Status lines: `Being revised` (in_progress), `Waiting for sign-off` (in_review), `Signed off by {name} on {date}` (released), `Rejected by {name}: {reason}` (open with a latest rejection), `Not started` (open with no rejection).
  - Submission summary: `Submission {n}, all checks passed` / `Submission {n}, 1 check failed` / `Submission {n}, {k} checks failed`.
  - Sample-mode indicator: `Sample data. Nothing here is saved or real.`
  - Approve and reject buttons: `Approve submission {n}`, `Reject submission {n}`.
  - Dates: `toLocaleDateString("en-GB", { day: "numeric", month: "short", year: "numeric" })`, e.g. `26 Nov 2026`.
- **The UI never decides pass or fail.** It shows `CheckResult`s and places markers from numbers in `SettingView.canonical`. It never parses instrument values out of step text.
- **Approval always names a submission number.** The client refuses approve or reject unless the order is `in_review` and the number is the latest submission. A rejection needs a non-blank name and reason. An approval needs a non-blank name.
- **Interaction:**
  - Touch targets at least 40 px.
  - Visible focus (`outline: 2px solid var(--indigo)`).
  - The only animation is the output panel opening and closing, and it is disabled under `prefers-reduced-motion: reduce`.
- **Playwright in this sandbox:** if `PLAYWRIGHT_CHROMIUM_EXECUTABLE` is set, `playwright.config.ts` passes it as `launchOptions.executablePath`. Run with `PLAYWRIGHT_CHROMIUM_EXECUTABLE=/opt/pw-browsers/chromium npm run test:e2e -- --trace off`.

## Review Focus

1. **A URL with an unknown project or experiment id** (a stale bookmark) shows `That project or experiment doesn't exist in this lab.` and a link home. The app doesn't crash. Tested in Task 5.
2. **A setting value outside its limits** puts the marker at the nearest end of the strip, never off it, and the step's failing check detail is shown. Tested in Task 2 (unit) and Task 7 (seeded failure).
3. **An empty or whitespace-only message:** Send is disabled and no message is created. Tested in Task 7.
4. **A blank name on approve, or a blank reason on reject:** the confirm button stays disabled, and the client refuses it too. Tested in Tasks 4 and 8.
5. **A double click on Send or Approve:** only one action happens, because buttons are disabled while a request is pending. The client refuses a second approval because the order is already released. Tested in Tasks 4 and 8.

### Task 4: Sample client

**Files:**
- Create: `lab-factory/web/lib/sample/client.ts`
- Test: `lib/sample/client.test.ts`

**Interfaces:**
- Consumes: `createSeed`, `coomassieFollowUp` and `SampleState` (Task 3), plus the types (Task 2).
- Produces: `createSampleClient(options?: { delayMs?: number; now?: () => Date }): LabFactoryClient & { reset(): void }`.
  - Default `delayMs` is 0. Each method awaits the delay before resolving.
  - `now` stamps every `at` field.

**Behavior:**
- **`getWorkspace`**
  - `procedure` is the experiment's newest work order, with its latest submission, the step views and the history.
  - `analysis_app` is set only where seeded.
  - It throws `ClientError("not_found")` for unknown ids, and so do the other lookups.
- **`sendMessage(experimentId, text, attachments)`**
  - It refuses with `ClientError("invalid")` when `text.trim()` is empty and there are no attachments.
  - It appends the person's message, recording the attachment names.
  - **Coomassie with at least one attachment, while its newest order is WO-1:** apply `coomassieFollowUp(attachments[0].name, now)` and append a factory message:
    > I added {name} to this experiment and rewrote the procedure. Every check passes, and it’s waiting for sign-off.

    with `output_ref` `{ work_order_id: "WO-2", summary: "Submission 1, all checks passed" }`.
  - **Anything else:**
    > This is sample data, so the factory can’t act on that here. In the live app it would answer and update the procedure.

  - It returns the new messages.
- **`approve(workOrderId, submission, person)`**
  - Refused (`"refused"`) unless the status is `in_review` and `submission` is the latest. The refusal message for a stale number is `Submission {n} is not the latest. Review submission {latest}.`
  - Refused (`"invalid"`) if `person.trim()` is empty.
  - On success, sets `released`, sets `released_submission`, and appends an `approved` event whose `note` is the artifact digest.
- **`reject(workOrderId, submission, person, reason)`**
  - The same refusals, plus `"invalid"` for a blank reason.
  - On success, sets status `open` and appends a `rejected` event with `note = reason`. The factory then appends a message: `Thanks. I’ll revise the procedure to address: {reason}`.
- **`needsAttention(labId, role)`**
  - `approver`: orders that are `in_review`, with `kind: "sign_off"`.
  - `researcher`: orders that are `released` (`"signed_off"`), plus `open` orders whose latest event is `rejected` (`"rejected"`).
  - `title` is the experiment's title.
- **`createProject` and `createExperiment`**
  - New ids are slugs of the title plus a counter.
  - An experiment's title is its description truncated to 60 characters at a word boundary.
  - A new experiment gets the person's description as its first message and the sample-mode reply.
  - Blank input is `"invalid"`.
- **`reset()`** restores `createSeed()`.
